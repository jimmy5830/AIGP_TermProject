## 2. V1 → V3 변경사항 및 설계 의도

V3의 모든 변경은 동료가 설계한 `BT_modification.txt`의 **Outranging Phase Defender** 전략을 RL 보상 구조로 번역한 결과이다. BT는 3가지 거리 구역(Kill Zone / Enemy Zone / Safe Zone)과 3단계 체력 구간(Phase 1~3)을 명시적 코드로 구현하지만, RL은 이를 **보상 신호로 암묵적으로 유도**한다.

---

### 2-1. 3-Zone 거리 보상 (Kill Zone 유지 유도)

**변경 전 (V1)**
```csharp
private const float PenaltyTooClose = -0.01f;
private const float SafeDistance    = 1.5f;

// ApplyStepRewards 내
if (dist < SafeDistance)
    AddReward(PenaltyTooClose);
```

**변경 후 (V3)**
```csharp
private const float KillZoneMin      = 1.4f;
private const float KillZoneMax      = 1.7f;
private const float EnemyZoneMax     = 1.2f;
private const float RewardKillZone   =  0.005f;
private const float PenaltyEnemyZone = -0.02f;

// ApplyStepRewards 내
if (dist >= KillZoneMin && dist <= KillZoneMax)
    AddReward(RewardKillZone);
else if (dist < EnemyZoneMax)
    AddReward(PenaltyEnemyZone);
```

**설계 의도**

BT 전략의 핵심은 **Kill Zone(1.4~1.7f) 점유**이다. 이 구역은 자신만 일방적으로 공격 가능한 비대칭 구역으로, BT는 모든 Phase에서 이 구역을 최우선 점유 목표로 삼는다. V1의 단일 페널티(`<1.5f`)는 너무 가까이 붙는 것만 억제할 뿐 Kill Zone을 정밀하게 유도하지 못했다. V3는 다음 두 가지를 동시에 달성하려 했다:

- Kill Zone에 머무는 행동 자체에 **소액 보상**을 부여하여 양의 신호로 유도
- Enemy Zone(<1.2f) 진입에 **강화된 페널티(-0.02)**를 부여하여 위험 구역 회피를 강제

**의도 충족 여부**

충족됨. V1은 100~300k 구간에서 Mean Reward가 +5~+6에 묶인 고원(plateau)을 보였는데, 이는 거리 보상이 불명확하여 위치 전략을 학습하지 못한 결과로 해석된다. V3는 동일 구간(100~300k)에서 +40~+86까지 급상승하였으며, 이는 Kill Zone 보상이 탐색 방향을 조기에 명확히 제시했음을 나타낸다. 또한 V1에서 발생한 **Policy Collapse(820k, -8.032)**는 불안정한 위치 전략으로 인해 과도한 고위험 행동을 탐색한 결과인데, V3에서는 이와 같은 붕괴가 전혀 관찰되지 않았다.

### 2-2. Poke & Retreat 시퀀스 보상

**변경 전 (V1)**  
Attack과 Dodge를 독립된 행동으로만 취급. 두 행동의 순서 관계에 대한 보상 없음.

**변경 후 (V3)**
```csharp
private const float RewardPokeRetreat =  0.15f;
private bool  _didAttackLastStep;

// ApplyStepRewards 내
if (combatAction == 2 && _didAttackLastStep && cooldownSystem.IsDodgeReady())
    AddReward(RewardPokeRetreat);

_didAttackLastStep = (combatAction == 3 && cooldownSystem.IsAttackReady());
```

**설계 의도**

BT의 Phase 1·2에서 공통으로 나타나는 핵심 루프는 **"공격(Attack) → 즉시 뒤로 회피(Dodge Back)"**이다. 이를 Poke & Retreat라 부르며, 이 패턴은 Kill Zone에서 공격하고 즉시 벗어남으로써 상대의 반격을 무력화한다. V1의 보상 구조는 공격과 회피 각각에 개별 보상을 부여했지만 이 **순서 조합**에 대한 신호가 없었다. V3는 Attack 직후 Dodge를 선택했을 때 추가 보상을 부여하여, 단발 행동 학습을 넘어 **2-step 전술 패턴의 학습**을 유도하였다.

**의도 충족 여부**

부분적으로 충족됨. V3에서 Policy Collapse 없이 안정적으로 고보상 구간을 유지한 것은 Poke & Retreat 패턴이 학습되었음을 시사한다. 공격 후 즉시 후퇴하는 패턴이 과도한 위험 탐색(V1의 730k +34, Std 21)을 방지하고 안정적인 전략으로 수렴하는 데 기여했을 것으로 해석된다. 다만 실제 Poke & Retreat 빈도를 직접 로깅하지 않아 정량적 검증은 불가능하다.

---

### 2-3. 상대 공격 쿨타임 Observation 추가 (Space Size 11 → 12)

**변경 전 (V1)**  
상대의 행동 관찰: `IsAttacking(bool)` 1개만 존재. 상대가 공격 가능한 상태인지 여부는 관찰 불가.

**변경 후 (V3)**
```csharp
// CollectObservations 내 [12]번
float oppAtkCooldown = opponentCooldownSystem != null
    ? opponentCooldownSystem.GetAttackCooldownRatio()
    : 0f;
sensor.AddObservation(oppAtkCooldown);
```

**설계 의도**

BT Phase 3의 핵심 조건은 **"상대 공격 쿨다운 중에만 Poke 수행"**이다. 즉 상대가 공격할 수 없는 타이밍에만 선제 공격을 감행하여 안전한 기회를 만드는 것이다. V1은 상대의 `IsAttacking` 여부만 알 수 있어 공격 직후 쿨다운 상태를 구분하지 못했다. V3는 상대 공격 쿨타임 진행률을 Observation에 추가함으로써, 에이전트가 **"상대가 공격 직후 쿨다운 상태"**를 인식하고 그 타이밍에 반격하는 패턴을 발견하도록 유도하였다.

**의도 충족 여부**

충족됨. V3의 930k에서 Mean Reward +124.520, **Std 9.003**을 기록하였다. Std가 9는 V1·V3 전체 로그에서 역대 최저값으로, 이는 에이전트가 거의 결정론적인 일관된 전략을 구사하고 있음을 의미한다. 랜덤 탐색 없이 안정된 고보상 전략을 반복 실행한다는 것은 상대의 쿨타임 패턴을 파악하고 타이밍 기반 공격을 학습했다는 강력한 증거이다.

### 2-4. Finisher 모드 추가 보상

**변경 전 (V1)**  
양쪽 체력 상태에 무관하게 반격 성공 보상 = +0.5 고정.

**변경 후 (V3)**
```csharp
private const float RewardFinisher = 0.3f;

// DetectHPChanges 내
if (targetHPDecreased && (_didBlockLastStep || _didDodgeLastStep))
{
    AddReward(RewardCounterAttack);  // +0.5
    if (self.CurrentHealthRatio < 0.3f && opponent.CurrentHealthRatio < 0.3f)
        AddReward(RewardFinisher);   // +0.3 추가 (총 +0.8)
}
```

**설계 의도**

BT Phase 3는 기본적으로 생존 우선이지만, **상대 HP도 30% 이하일 때 Finisher 모드로 전환**하여 Phase 1·2 수준의 공격성을 발휘한다. V1은 에피소드 후반 저체력 상황에서도 생존에만 집중하여 마무리 기회를 놓치는 경향이 있었다. V3는 양쪽 모두 저체력인 결정적 순간에 반격 성공 시 추가 보상(+0.3)을 부여함으로써, **에피소드 막판 공격적 마무리 전환**을 유도하였다.

**의도 충족 여부**

충족 가능성 있음. V3의 후반(900k~1M) 평균 보상이 +103~+124로 V1 후반(900k~1M, +29~+68) 대비 약 2~3배 높다. 이는 에피소드를 승리로 마무리하는 빈도가 증가했음을 시사한다. 다만 Finisher 직접 트리거 횟수를 별도 로깅하지 않아 정확한 기여도 분리는 불가능하다.

## 4. 단계별 비교 분석

### Phase 1 — 초반 탐색 (0 ~ 100k)

| 항목 | V1 | V3 |
|---|---|---|
| 양수 돌파 | 40k | 20k |
| 100k Reward | +5.792 | +40.944 |

V3는 V1보다 **7배 높은 100k Reward**를 기록하며 초반 탐색 속도에서 압도적 차이를 보였다. Kill Zone 보상이 탐색 방향을 즉시 안내하여 음수 보상 구간을 빠르게 탈출한 것으로 해석된다.

### Phase 2 — 고원 및 전략 수렴 (100k ~ 400k)

| 항목 | V1 | V3 |
|---|---|---|
| 100~300k 평균 | +5~+6 (고원) | +40~+86 (지속 상승) |
| 전략 전환 시점 | 330k | 130k |

V1의 가장 두드러진 약점은 100~300k에서 Mean Reward +5~+6에 고착된 **장기 고원(plateau)**이다. 거리 보상이 불명확하여 에이전트가 어떤 전략이 유리한지 학습하지 못하고 소극적 생존(생존 보상 누적)에만 의존한 결과이다. V3는 Kill Zone 보상과 Poke & Retreat 보상이 이 구간에서 지속적인 상승 기울기를 만들어 고원 현상이 발생하지 않았다.

### Phase 3 — 고위험 탐색 및 Policy Collapse (400k ~ 900k)

| 항목 | V1 | V3 |
|---|---|---|
| Policy Collapse | 820k (-8.032) | **없음** |
| 분산 피크 | 730k Std 21.417 | 740k Std 22.722 (이후 감소) |

V1은 730k에서 고위험 전략(+34, Std 21)을 탐색하다 820k에 Policy Collapse로 붕괴했다. 이는 명확한 위치 전략 없이 높은 보상만 추구하다 불안정 구간에 진입한 결과이다. V3도 740k에서 유사한 Std(22.7) 수준의 탐색을 거쳤지만, Kill Zone 유지 보상이 정책에 안정적 기준점을 제공하여 붕괴 없이 수렴으로 전환되었다.

### 종합 평가

V3는 `BT_modification.txt`의 핵심 전략 요소를 RL 보상 구조로 번역하는 시도에서 뚜렷한 성과를 거두었다. BT가 코드로 명시하는 Kill Zone 점유, Poke & Retreat 루프, 타이밍 기반 공격이라는 세 가지 전략적 패턴을 RL이 보상 신호를 통해 자율적으로 발견하도록 유도하였으며, V1 대비 최종 보상 198% 향상과 Policy Collapse 소멸이라는 구체적 결과로 나타났다.

특히 930k의 Std 9.003은 단순한 보상 수치 개선을 넘어, 에이전트가 **일관된 전술적 판단 기준을 확립했다**는 질적 전환을 보여주는 지표이다. BT가 명시적 규칙으로 달성하는 전략적 일관성을 RL이 학습을 통해 재현했다는 점에서, V1→V3 개선은 BT 전략 분석이 RL 설계에 유효하게 적용될 수 있음을 실증한다.
